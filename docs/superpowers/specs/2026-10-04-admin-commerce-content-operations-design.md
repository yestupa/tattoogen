## 1. 目标

本次迭代把 Tattoo Generator 从已上线的第一版扩展为可由非技术人员日常运营的产品。管理员应能在后台维护价格、Credit、折扣、双语文章、用户、模型用量与工单；公开页面、认证页面和用户面板继续遵循已经确认的视觉系统。

交付范围包括：

- 将 success@yestupa.com 设为超级管理员
- 修复文章编辑时非正文字段丢失的问题
- 修复文章分类选择后显示内部字符的问题
- 增加价格、Credit 与折扣管理
- 增加英文和中文文章的独立编辑与发布
- 增加 FastClaw 用户 token 用量管理
- 隐藏普通用户的 API Key 板块
- 移除 ShipAny 品牌水印与公共入口
- 增加注册和付款邮件通知
- 增加公开 Contact 工单页面
- 定制隐私政策与服务条款
- 增加普通用户删除功能
- 优化 404 页面
- 强制邮箱激活
- 保证 Sitemap 根据公开内容自动更新
- 完成测试、GitHub 推送与 Cloudflare 正式部署

## 2. 已选方案

采用后台统一管理方案。

该方案保留现有 TanStack Start、D1、Better Auth、FastClaw 和支付模块，通过新的服务端模块与数据库表，把以下数据统一为服务端权威来源：

- 商品基础价格和 Credit
- 当前有效折扣
- 英文与中文文章
- FastClaw 用户映射与用量缓存
- 注册、付款和工单邮件事件
- 公开联系工单

页面只能提交商品标识、表单内容和操作意图。金额、Credit、折扣、权限、用户身份和发布状态均由服务端重新读取和验证。

## 3. 价格与 Credit

### 3.1 商品范围

保留现有套餐名称与商品标识：

- Lite 月付与年付
- Pro 月付与年付
- Ultra 月付与年付
- 三个 Credit 充值包

后台价格页面列出所有商品。超级管理员可调整：

- 售价，按最小货币单位保存
- Credit 数量
- Credit 有效天数
- 是否允许新订单购买

### 3.2 数据模型

新增 pricing_override 表：

- product_id，唯一商品标识
- price_in_cents
- credits
- credits_valid_days
- enabled
- updated_by
- created_at
- updated_at

代码中的 pricingCatalog 继续作为安全默认值。数据库覆盖值通过严格校验后合并到默认目录。缺失或无效的数据库值不会替换安全默认值。

### 3.3 权威目录

新增服务端 pricing catalog 模块，负责：

- 合并默认商品与后台覆盖值
- 计算当前有效折扣
- 返回公开页面所需的脱敏价格信息
- 为结账接口提供最终商品信息
- 为 Credit 充值弹窗提供商品信息

公开价格页面和结账接口读取同一模块。浏览器提交的 price、credits、plan_name 等字段不参与金额计算。

### 3.4 现有订阅

- 后台改价只影响之后创建的订单。
- 已有 Stripe 等订阅继续使用创建订阅时的价格。
- Credit 数量在创建订单时写入订单快照，后续后台改价不会改变已付款订单。

## 4. 折扣活动

### 4.1 字段

新增 discount 与 discount_product 表。

discount 包含：

- id
- internal_name，仅后台显示
- display_name_en
- display_name_zh
- percentage，整数百分比，范围 1 至 99
- starts_at，UTC 时间
- ends_at，UTC 时间
- enabled
- created_by
- created_at
- updated_at

discount_product 连接折扣与一个或多个商品标识。

### 4.2 计算规则

- 折扣不会叠加。
- 同一商品同时命中多个活动时，采用折扣比例最高的活动。
- 比例相同时，采用开始时间更早的活动。
- 后台保存时提示重叠时段和重复商品，但保留确定性的服务端兜底规则。
- 折后金额使用整数分计算并四舍五入，最低为 1 分。
- 开始时间包含，结束时间不包含。
- 前端显示原价、折后价、对应语言的展示名称和结束时间。

### 4.3 订阅行为

活动期间创建的新订阅锁定当时的折后订阅价格。活动结束不会改写已经存在的订阅。新订单恢复使用届时有效的基础价格或其他活动价格。

### 4.4 支付兼容

- Stripe、支付宝和微信支付使用服务端计算后的动态金额。
- Creem 使用外部固定商品。当前有效价格与 Creem 固定商品可能不一致时，服务端阻止结账并显示管理员可操作的配置提示，防止展示金额与扣款金额不一致。
- 订单保存折扣名称、折扣金额和最终金额。支付回调缺少折扣字段时，不覆盖应用侧已经保存的折扣快照。

## 6. FastClaw token 用量

### 6.1 用户映射

新增 fastclaw_user_mapping 表：

- user_id，网站用户 ID
- external_id，使用稳定的网站用户 ID
- fastclaw_user_id
- provisioned_at
- updated_at

首次调用 Agent 前，通过 FastClaw 的用户接口幂等创建或读取映射。已有用户再次调用时复用映射。API Key 始终保存在服务端配置，不发送到浏览器、日志或公开接口。

### 6.2 用量查询

使用 FastClaw 官方用量接口按映射用户查询：

- inputTokens
- outputTokens
- cacheReadTokens
- cacheCreationTokens
- requestCount
- 每日明细

新增 fastclaw_usage_cache 表，缓存 7 天、30 天和 90 天聚合结果。缓存默认十分钟，管理员可手动刷新。单个用户查询失败不会导致整页失败。

### 6.3 后台页面

新增用量页面，支持：

- 用户邮箱与名称搜索
- 7 天、30 天、90 天切换
- 输入、输出、缓存与总 token
- 请求次数
- 同期 Credit 消耗
- 最近同步时间
- 单用户每日趋势

大白话说明：token 是模型实际处理的文字量，Credit 是网站扣给用户的站内额度。后台同时显示两者，避免把它们误认为同一个数字。

## 7. 用户管理与删除

### 7.1 权限

删除用户只对超级管理员开放。

以下操作被阻止：

- 删除当前登录账号
- 删除拥有超级管理员角色的账号
- 删除仍拥有后台管理权限的账号

如需删除管理员，必须先移除其管理角色。

### 7.2 确认与结果

- 管理员必须在确认弹窗输入完整目标邮箱。
- 服务端再次校验目标、当前会话与角色。
- 删除在数据库事务中完成。
- 会话和账号凭据被删除，旧会话立即失效。
- 同一邮箱之后可以重新注册为全新用户。

### 7.3 依赖清理

已有级联关系继续处理 session、account、订单、订阅、Credit、API Key、角色、AI 任务、聊天与文章等记录。

事务显式处理当前未配置级联的记录：

- ticket_message
- ticket
- user_invite
- invite_code.created_by 置空
- FastClaw 映射与用量缓存

删除接口不会接收任意表名、SQL 或文件路径。

## 15. 已确认的问题原因

### 15.1 文章编辑字段丢失

当前代码在编辑弹窗挂载前重置表单，弹窗挂载后字段可能用空默认值重新初始化。随后异步请求只回填正文，因此标题、摘要、分类、作者和状态看起来全部丢失。

修复方式：先请求完整文章，成功后一次性设置编辑记录并初始化全部字段。加载期间显示按钮状态，失败时保持列表不变。

### 15.2 分类显示内部字符

分类字段保存 ID，选项又是异步加载。当前选择器在选项尚未就绪时会直接显示 ID。

修复方式：等待分类选项与文章详情就绪，并由组件显式使用 ID 对应的 title 作为显示值。

- 支付与通知处理具备幂等键。
