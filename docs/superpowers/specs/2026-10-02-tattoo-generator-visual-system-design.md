# Tattoo Generator 全站视觉系统设计

日期：2026-10-02

状态：已由用户确认设计方向，等待用户审阅书面规格

## 1. 目标

为 Tattoo Generator 建立覆盖全站的统一视觉系统。参考 tat.ink 的清晰布局、紫色交互提示、轻量卡片和生成器工作台结构，同时保留当前产品的米白纸张质感、纹身工作室气质和对话式 Agent 流程。

改造完成后，营销页、登录注册、生成器、用户后台、管理后台、内容页面、空状态和错误页面应当呈现为同一个品牌产品。

## 2. 设计原则

- 参考布局规律，不复制 tat.ink 的图片、文案、图标组合或品牌素材。
- 视觉改造不改变现有登录、权限、计费、积分、FastClaw、支付和数据库行为。
- 优先建立共享变量与组件，再处理页面级样式，避免每个页面产生一套独立规则。
- 浅色模式保持温暖，深色模式保持清晰，不使用纯黑与纯白的大面积强对比。
- 所有关键操作在桌面、平板和手机上都应具有清楚的层级和足够的触控区域。

## 3. 已选择的实施方案

采用共享设计系统与页面外壳改造方案。

本方案会统一：

- 全局颜色、字体、圆角、阴影、间距和动效变量
- 按钮、输入框、卡片、徽章、弹窗、表格和状态反馈
- 营销页页头与页脚
- 登录注册外壳
- 用户后台与管理后台外壳
- Agent 工作台
- 404、无权限、加载失败、空列表和无搜索结果状态

不采用逐页复制参考站的方式，也不重写现有业务架构。

## 4. 视觉基础

### 4.1 浅色模式

- 页面背景：暖米白 `#FBF8F3`
- 主卡片：柔和白 `#FFFDFC`
- 主要文字：墨黑 `#171827`
- 次要文字：暖灰蓝 `#676779`
- 主色：深紫 `#7137F2`
- 主色悬停：浓紫 `#5F28D8`
- 淡紫表面：`#F1EAFF`
- 边框：暖灰 `#E6E0D8`
- 成功状态：柔和墨绿
- 警告状态：暖琥珀
- 错误状态：低饱和红

### 4.2 深色模式

- 页面背景：深墨黑 `#17151C`
- 主卡片：暖黑灰 `#211E28`
- 次级表面：`#2A2632`
- 主要文字：暖白 `#F5F1EA`
- 次要文字：`#AAA3B4`
- 主色：亮紫 `#9668FF`
- 边框：`#393441`

深色模式保留手动切换按钮，并尊重系统初始偏好。

### 4.3 字体

- 页面标题和功能标题使用粗体无衬线字体，形成清楚的产品感。
- 正文、表单和数据表使用现有 Inter 字体。
- 品牌名称和少量编辑性标题保留当前衬线斜体，提供纹身工作室气质。
- 中文标题优先使用系统黑体，避免加载体积过大的中文网络字体。

### 4.4 形状、阴影与动效

- 大卡片圆角：18 像素
- 普通卡片圆角：14 像素
- 输入框和按钮圆角：12 像素
- 标签与状态徽章：胶囊形
- 阴影使用低透明度暖灰紫，不使用厚重黑色投影。
- 页面进入和卡片悬停只使用轻微位移与透明度变化。
- 用户启用减少动态效果时，关闭非必要动画。

## 5. 共享组件架构

### 5.1 全局变量

在全局样式中集中管理颜色、圆角、阴影、侧栏和图表变量。现有 shadcn 风格组件继续通过语义变量取色，减少页面内硬编码颜色。

### 5.2 页面外壳

建立或整理以下共享外壳：

- 营销页面外壳：站点页头、正文容器、页脚
- 认证页面外壳：品牌区域、表单区域、帮助链接
- 用户后台外壳：侧栏、移动端顶部栏、页面标题区、用户菜单
- 管理后台外壳：复用用户后台结构，提供更高信息密度
- Agent 工作台外壳：导航、对话区、设置与预览区

### 5.3 状态组件

建立统一的：

- 页面加载状态
- 空列表状态
- 无搜索结果状态
- 权限不足状态
- 请求失败状态
- 404 页面

状态组件支持标题、说明、插图和一至两个操作按钮，页面只传入内容与操作。

### 5.4 基础组件

统一按钮、卡片、输入框、文本域、选择器、标签页、弹窗、抽屉、表格和提示消息的：

- 高度与内边距
- 圆角
- 边框颜色
- 聚焦状态
- 禁用状态
- 错误状态
- 深色模式

## 6. 页面设计

### 6.1 首页和营销页面

- 页头保持通透，桌面端导航居中，品牌在左，语言、主题和主要操作在右。
- 首页首屏使用左侧价值主张与右侧纹身作品的分栏结构。
- 标题中的重点短语使用深紫色，不使用整块紫色背景。
- 主要按钮使用深紫填充，次要按钮使用暖白描边。
- 功能、作品、流程、价格和 FAQ 采用统一卡片与标题节奏。
- 价格页、博客、条款和隐私页共用正文宽度、页头与页脚。

### 6.2 登录注册与账号恢复

桌面端使用居中的双栏大卡片：

- 左侧展示原创纹身线稿、品牌价值点和安全提示。
- 右侧承载邮箱密码、第三方登录、条款和辅助链接。
- 注册、登录、忘记密码、重置密码、验证邮箱和邀请码页面共享同一外壳。
- 手机端隐藏大型装饰图，将价值点压缩为简短横向提示。
- 不改变现有认证提供商、回调地址和表单验证。

### 6.3 Agent 生成器

- 左侧为品牌导航、会话历史和用户入口。
- 中间为对话记录、提示词示例和消息编辑器。
- 右侧为作品预览、生成设置和下载操作。
- 当前导航使用淡紫背景、深紫文字和紫色图标。
- 提示词编辑器使用更大的圆角容器和清楚的附件区域。
- 加载、扣除积分、失败退款和流式响应行为保持不变。
- 平板端折叠左侧导航，手机端将设置与预览改为抽屉或分段视图。

### 6.4 用户后台

Chats、Library、Editor、Profile、Billing、Credits、Payments、API Keys 和 Tickets 使用相同结构：

- 统一页面标题、说明和主操作位置
- 统一卡片、筛选器、空状态和分页
- 用户信息与套餐信息集中在侧栏底部用户菜单
- 宽表格在自己的容器内横向滚动，页面本身不产生横向溢出

### 6.5 管理后台

- 与用户后台共享品牌侧栏、移动端顶部栏和表面样式。
- 管理页面使用较紧凑的间距和更高的数据密度。
- 用户、角色、权限、积分、订单、订阅、内容与设置页面使用一致的筛选和表格操作。
- 危险操作保留红色语义，不使用紫色弱化风险。
- 权限检查、路由保护和服务端接口保持不变。

### 6.6 404 与异常页面

- 使用自有品牌图形或纹身线稿，不使用参考站的橙色 404 图形。
- 404 数字使用深紫轮廓或淡紫渐变。
- 提供返回首页和开始创作两个操作。
- 中文和英文文案均通过现有国际化系统提供。
- 根路由配置统一的未找到页面，避免浏览器显示框架默认错误界面。

## 7. 响应式行为

- 桌面宽度从 1280 像素起显示完整三栏工作台。
- 平板宽度在 768 至 1279 像素间折叠侧栏，保留主要内容与预览。
- 手机宽度低于 768 像素时使用单栏内容、底部或抽屉式辅助面板。
- 所有页面在 390 像素宽度下不产生横向滚动。
- 触控按钮最小可点击区域为 44 像素。

## 8. 可访问性

- 文本与背景满足 WCAG AA 对比度目标。
- 所有交互控件具有可见键盘焦点。
- 图标按钮提供可读的辅助标签。
- 表单错误与对应字段关联。
- 弹窗打开后管理焦点，关闭后恢复到触发按钮。
- 装饰图片使用空替代文本，内容图片提供有意义的替代文本。

## 9. 数据流与功能边界

本次改造只调整表现层和页面组合方式。以下行为不改变：

- Better Auth 登录与会话
- RBAC 权限与超级管理员逻辑
- FastClaw 服务端代理与 Agent 标识
- API Key 服务端存储和加密
- D1 数据库结构与迁移方式
- 积分扣除、失败退款和任务记录
- 支付、订阅、邮件和对象存储配置
- 中英文路由与 SEO 生成逻辑

FastClaw 密钥不会写入前端代码、Git 历史或公开环境变量。用户注册并获得超级管理员权限后，在管理后台保存该密钥。

## 10. 错误处理

- 页面级请求失败使用统一错误状态并提供重试操作。
- 表单错误显示在字段附近，同时保留顶部提示消息。
- Agent 生成失败保留服务端脱敏后的错误信息，并保持积分退款逻辑。
- 无权限访问显示品牌化提示并提供安全返回路径。
- 未找到页面返回正确的 404 HTTP 状态。

## 12. GitHub 与 Cloudflare 上线

实施完成并通过验证后：

1. 检查最终差异并运行提交前安全扫描。
2. 提交设计改造并推送到 `yestupa/tattoogen` 的 main 分支。
3. 在 Cloudflare 账号中创建 `tattoo-generator` D1 数据库。
4. 生成并执行数据库迁移，初始化基础 RBAC 数据。
5. 配置认证和配置加密所需的服务端密钥。
6. 使用项目的 `cf:deploy` 脚本发布 `tattoo-generator` Worker。
7. 绑定 `bestaitattoogenerator.com` 自定义域名。
8. 检查首页、公开配置、robots、sitemap、中英文页面和认证入口。

首次 D1 创建和最终公开发布遵守 Cloudflare 部署流程中的安全确认点。

## 13. 验收标准

- 全站页面明显属于同一视觉系统。
- 品牌保持米白、墨黑和深紫的固定组合。
- 登录页、用户后台、管理后台和 404 页面不再呈现模板默认风格。
- 浅色与深色模式均无不可读文字或失去边界的控件。
- 桌面、平板和手机无非预期横向滚动。
- 中英文页面布局稳定。
- 现有认证、权限、FastClaw、积分、支付和内容功能没有回归。
- 自动检查和浏览器检查全部通过，或清楚记录任何已有的非阻塞提示。
- GitHub main 分支包含最终改动。
- bestaitattoogenerator.com 能通过 HTTPS 正常访问并返回正确页面。

## 14. 风险与控制

- 风险：共享组件改动影响大量页面。
  - 控制：先调整语义变量和基础组件，再逐类检查页面，避免一次性重写业务组件。
- 风险：三栏工作台在平板和手机上拥挤。
  - 控制：使用折叠侧栏和抽屉，将对话区保持为唯一主区域。
- 风险：深色模式中的紫色和图片过亮。
  - 控制：深色模式使用独立主色与阴影变量，并进行真实浏览器检查。
- 风险：认证与后台改造误触业务逻辑。
  - 控制：只调整外壳与样式，保持现有 API、表单提交和权限判断代码路径。
- 风险：上线前缺少生产数据库或服务端密钥。
  - 控制：部署前单独检查 D1、迁移、RBAC、认证密钥和配置加密密钥。
