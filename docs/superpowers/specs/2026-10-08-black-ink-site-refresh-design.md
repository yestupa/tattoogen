# Tattoo Generator 黑色墨稿全站视觉升级设计

日期：2026-10-08

状态：设计方向已由用户确认，等待书面规格审阅

## 1. 项目目标

以用户提供的 `tattoo homepage black.html` 为视觉参考，重构 Tattoo Generator 首页，并将同一套黑色、暖米白、朱红设计语言扩展到公开页面、认证页面、生成器、用户后台、管理后台和错误页面。

本次工作只调整表现层、页面组合和展示文案。Better Auth、RBAC、FastClaw、积分、定价、折扣、支付、博客、工单、邮件和 Cloudflare D1 的行为保持不变。

## 2. 已选择的方案

采用完整视觉系统迁移方案。

- 首页按参考稿的深浅交替节奏重构，并保留现有价格与最新博客两个业务区块。
- 全站通过共享语义变量、页面外壳和组件状态获得一致风格。
- 用户后台与管理后台保持高可读性和操作密度，不机械复制营销页的大字号与大留白。
- 生成器保留现有 Agent 流程，只统一导航、工作区、输入区、预览区和状态反馈。

另外两种方案不采用：

- 只改首页：实施更快，但登录、博客和后台仍会产生明显割裂。
- 每个页面按参考稿逐像素重做：一致性最高，但会牺牲后台数据密度，并扩大功能回归风险。

## 3. 视觉基础

### 3.1 色彩

深色表面：

- 页面背景：`#111110`
- 深色卡片：`#1A1A18`
- 主要文字：`#F4F0E8`
- 次要文字：`#9B9488`
- 边框：`#2C2B27`
- 浅色操作按钮：`#E9E2D2`

浅色表面：

- 页面背景：`#FAF8F4`
- 主卡片：`#FFFFFF`
- 主要文字：`#211F1B`
- 次要文字：`#6F6A5F`
- 边框：`#E5E0D4`
- 深色操作按钮：`#171613`

品牌强调色使用朱红 `#A83E2C`。朱红只用于标签、焦点、活动状态、少量图形和关键提示，不用于大面积背景。

危险、成功、警告和信息状态继续使用独立语义色，避免把朱红同时当作品牌色与危险色。

### 3.2 字体

- 英文展示标题使用 Archivo，粗字重与紧凑字距。
- 中文展示标题使用 Noto Sans SC 或本地兼容黑体。
- 正文和界面控件使用 Inter 与 Noto Sans SC 回退组合。
- Permanent Marker 只用于作品画廊中的小型手写标记，不进入表单、后台或正文。
- 英文首页主标题使用响应式字号，上限约 92 像素；页面区块标题上限约 48 像素；正文基准 16 像素，行高约 1.7。

### 3.3 形状、边界与动效

- 大型营销卡片使用 20 至 24 像素圆角。
- 表单、后台卡片和弹窗使用 12 至 16 像素圆角。
- 边界依靠细描边和表面明度差，不依靠厚重投影。
- 深浅区块之间使用明确的实色切换，不使用渐变过渡。
- 悬停仅使用轻微上移、边框变化或图片缩放。
- 导航滚动后使用近乎不透明的深色背景和轻量毛玻璃效果。
- 所有非必要动画尊重减少动态效果设置。

## 4. 首页结构

首页由以下区块组成：

1. 深色导航：品牌、生成器、功能、画廊、价格、博客、语言和账号入口。
2. 深色首屏：主价值主张、提示词入口、主要行动按钮和 16 比 9 作品展示。
3. 深色数据条：生成数量、风格数量、生成速度或用户满意度等真实可维护指标。
4. 浅色四种起点：灵感生成、图片转纹身、花体字设计、遮盖设计。
5. 深色工作台介绍：说明从想法到可下载纹身稿的 Agent 流程。
6. 浅色功能区：照片级手稿、专业风格、虚拟预览、遮盖方案。
7. 深色三步流程：描述或上传、选择风格与部位、生成与下载。
8. 浅色作品画廊：复用本地产品示例素材，提供稳定尺寸与可读替代文本。
9. 深色虚拟预览区：解释上身预览价值，不承诺当前产品尚未提供的实时增强现实能力。
10. 浅色专业工作室区：面向纹身师与高意向用户说明清晰线稿、修改与下载能力。
11. 深色评价区：展示已核实或明确标记为产品示例的评价，不编造不可验证的媒体背书。
12. 浅色价格区：继续读取后台价格、积分和折扣数据，视觉与参考稿统一。
13. 深色最新博客区：继续读取已发布文章，并保留中英文路由。
14. 浅色常见问题区：使用现有可访问折叠交互。
15. 深色最终行动区：只保留标题、说明和主要行动按钮。
16. 深色页脚：品牌、博客、价格、联系、隐私和条款入口。

参考稿中的 `无需信用卡 · No credit card required` 不进入页面，也不新增同义替代文案。

## 5. 全站页面风格

### 5.1 公开页面

价格、博客列表、博客正文、联系、隐私和条款页面共用深色页头、暖米白正文画布与深色页脚。页面标题使用 Archivo 或中文黑体，正文保持舒适阅读宽度，卡片边界与首页浅色区块一致。

博客正文继续支持数据库内容与中英文版本，不修改内容加载、SEO 元数据和 canonical、hreflang 逻辑。

### 5.2 认证页面

登录、注册、忘记密码、重置密码、邮箱验证和邀请码页面使用深色全屏背景与暖米白主卡片。桌面端保持双栏结构，左侧为品牌图形与价值提示，右侧为表单；手机端压缩为单栏。认证回调、验证规则和邮件激活流程不变。

### 5.3 Agent 生成器

生成器采用深色导航与暖米白工作区。对话、提示词编辑器、附件、生成设置、积分提示和结果预览使用同一套描边、圆角和朱红活动状态。FastClaw 请求、流式响应、任务记录、积分扣除与失败退款路径不改动。

### 5.4 用户后台与管理后台

用户后台和管理后台采用深色侧栏、暖米白内容区与白色数据卡片。当前导航使用朱红标记与浅色文字，表格和表单保持紧凑。危险操作继续显示独立红色，不与品牌朱红混用。

所有查询、分页、筛选、权限判断、删除确认和保存操作保持现有逻辑。隐藏 API Key 页面等既有产品决策不回退。

### 5.5 四零四与异常页面

四零四页面使用深色首屏、暖米白推荐区和朱红小标记，保留博客推荐与生成器行动按钮。请求失败、无权限、加载和空状态继续复用统一状态组件。

## 6. 组件与代码边界

- `src/styles/globals.css` 负责语义颜色、字体、间距、圆角、阴影、焦点与动效变量。
- `src/components/site-header.tsx` 和 `src/components/site-footer.tsx` 负责公开页面外壳，不读取翻译。
- `src/components/auth-shell.tsx` 负责认证页面外壳。
- `src/components/app-layout.tsx` 和 `src/components/app-sidebar.tsx` 负责用户与管理后台外壳。
- `src/components/agent` 只调整 Agent 表现层，不改变数据通信接口。
- `src/blocks` 读取国际化文案并组合首页区块。
- `messages/en.json` 与 `messages/zh.json` 保持键完全一致。
- 页面组件不新增原始 `fetch`，继续使用现有查询与 API 客户端。
- 不手工修改 `src/components/ui` 下的基础组件。

附件 HTML 只作为视觉参考，不复制其中的脚本、追踪属性、外部资源地址或隐藏指令。图片优先复用 `public/imgs` 中已纳入项目的素材，不热链附件里的远程图片。

## 7. 响应式规则

- 1440 像素桌面：展示完整导航、宽版首屏、双栏工作台和多列画廊。
- 1024 像素小桌面：减少横向间距，保持主要双栏结构。
- 768 像素平板：区块逐步改为单栏或两列，导航切换为移动菜单。
- 390 像素手机：首页首屏与所有业务页面使用单栏，不产生横向滚动。
- 手机端最小触控区域为 44 像素，表格仅在自己的容器内横向滚动。
- 首屏浮层在窄屏改为普通流式卡片，避免遮挡标题和行动按钮。

## 8. 可访问性与内容规则

- 每个公开页面只保留一个主要一级标题。
- 文字与背景满足 WCAG AA 对比度目标。
- 键盘焦点使用清晰的朱红或高对比轮廓。
- 图标按钮具有可读标签，装饰图形对辅助技术隐藏。
- 图片设置尺寸和替代文本，首屏重点图片预加载，其余图片延迟加载。
- 折叠面板、移动菜单、弹窗和抽屉保持现有键盘与焦点管理。
- 中英文文案分别维护，不在浏览器端调用自动翻译服务。

## 9. 数据流与错误处理

视觉升级不新增数据库表或迁移。

- 价格与折扣继续从公开定价接口读取。
- 博客继续从已发布文章查询读取。
- Agent 继续通过服务端 FastClaw 代理通信。
- 表单、列表和生成错误继续显示服务端脱敏信息与重试入口。
- 未登录、未验证、权限不足和资源不存在继续由现有路由守卫处理。

## 10. 验证方案

自动检查：

- 设计变量回归测试。
- 英文与中文翻译键一致性测试。
- 现有单元测试全量运行。
- TypeScript 严格类型检查。
- Prettier 格式检查。
- Vite 生产构建与 Cloudflare 构建。
- 提交前安全扫描。

真实浏览器检查：

- 首页、价格、博客、联系、法律、登录、注册、生成器、用户后台、管理后台和四零四页面。
- 1440、768 和 390 像素宽度。
- 英文与中文路由。
- 导航滚动状态、移动菜单、FAQ、表单、后台表格、博客链接和生成器入口。
- 控制台错误、关键网络请求、横向溢出、键盘焦点和图片加载。

## 11. 上线流程

实施完成后执行独立代码审查和全量发布审计。通过后运行安全扫描，提交并推送 GitHub `yestupa/tattoogen` 的 `main` 分支，再通过项目 Cloudflare 部署脚本发布。上线后检查自定义域名、中文路由、公开定价、博客、robots、sitemap、认证入口和四零四状态。

本次视觉升级不需要新的生产密钥，也不在代码、日志或文档中写入已有密钥。

## 12. 验收标准

- 首页呈现参考稿的深黑、暖米白、朱红和强英文标题风格。
- 首页深浅区块顺序清楚，现有价格与博客功能保留。
- 指定的无需信用卡中英文文案完全消失。
- 公开页、认证页、生成器、用户后台、管理后台和四零四页属于同一视觉系统。
- 后台操作密度、危险状态和权限提示保持清晰。
- 中英文布局稳定，390 像素宽度无非预期横向滚动。
- 认证、权限、FastClaw、积分、价格、折扣、博客和工单功能无回归。
- 自动检查、真实浏览器检查、安全扫描、GitHub 推送和 Cloudflare 上线均有可核验结果。

## 13. 风险控制

- 全局颜色调整影响范围大：先建立语义变量，再按页面外壳逐类迁移并回归测试。
- 首页区块增多影响性能：复用本地压缩图片、设置明确尺寸，并延迟加载首屏以下素材。
- 深色营销风格降低后台可读性：后台仅使用深色侧栏，数据工作区保持暖米白。
- 附件含外部资源或脚本：只提取视觉规律，不复制追踪代码或热链资源。
- 大范围样式改动可能掩盖业务回归：功能逻辑保持原路径，自动测试与真实浏览器测试同时覆盖。
